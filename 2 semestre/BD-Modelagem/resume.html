Modelos de Banco de Dados & Modelo Entidade-Relacionamento

Da abstração conceitual até o esquema físico: como representamos os dados de um sistema antes de escrever uma única tabela.

Entidade Atributo Relacionamento

§O que é um modelo de dados

Modelo de banco de dados é uma descrição dos tipos de informações que estão armazenadas em um banco de dados. Para construí-lo, usa-se uma linguagem de modelagem de dados — que pode ser textual ou gráfica.

Um modelo define um conjunto de conceitos para representar dados — como entidade, tabela e atributo — e existe em diferentes níveis de abstração, cada um respondendo a uma pergunta diferente sobre o sistema.

§Níveis de abstração

Do mais abstrato ao mais concreto, todo projeto de banco de dados passa por três camadas de modelagem:

Conceitual

Quais dados?

Alto nível de abstração, independente de SGBD. Preocupação com a semântica da aplicação. Principal exemplo: Modelo Entidade-Relacionamento.

Lógico

Como estruturar?

Representa os dados em alguma estrutura lógica — dependente do BD. Exemplos: Relacional (tabelas), Orientado a Objeto, Hierárquico, Rede, Dedutivo.

Físico

Como armazenar?

Descreve como os dados são salvos fisicamente — discos, métodos de acesso. Dependente tanto de software quanto de hardware.

§Fases do projeto de banco de dados

Do mundo real até o sistema em produção, o projeto percorre um caminho definido — cada fase entrega um esquema que alimenta a próxima:

1

Análise de requisitos

Parte-se do mundo real para levantar requisitos funcionais e requisitos de dados.

2

Projeto conceitual

Produz o esquema conceitual — o MER — a partir dos requisitos de dados.

Independente do SGBD
3

Projeto lógico

Traduz o MER para o esquema lógico — geralmente o Modelo Relacional.

Dependente do SGBD
4

Projeto físico

Define o esquema físico — o modelo de implementação real no disco.

Dependente do SGBD
5

Implementação das transações

Une o projeto físico ao projeto de programas de aplicação, gerando o sistema final.

§Modelo Entidade-Relacionamento (MER)

O MER é o principal modelo conceitual usado em projeto de banco de dados. É representado graficamente pelo Diagrama de Entidade-Relacionamento (DER), construído a partir de três formas geométricas — passe o cursor sobre cada uma:

Entidade

Retângulo — um objeto do mundo real sobre o qual mantemos dados.

Atributo

Oval — uma propriedade que caracteriza a entidade.

Relacionamento

Losango — uma associação entre duas ou mais entidades.

§Entidade

É a representação abstrata de um objeto do mundo real sobre o qual se deseja manter informações. Pode ter existência física (um funcionário) ou conceitual (um pedido). Cada ocorrência específica de uma entidade é chamada de instância.

Sistema Bancário
Cliente Conta Agência Banco
Sistema de Ambiente Empresarial
Produto Empregado Departamento Fornecedor

§Atributos

Atributos são as propriedades que caracterizam uma entidade. Por exemplo, a entidade Pedido precisa armazenar data, número, cliente, quantidade e valor unitário — cada um desses dados é um atributo, e eles se classificam assim:

Tipo Definição Exemplo
Simples Não pode ser subdividido quantidade
Composto Divide-se em subpartes com significado próprio endereço_cliente → rua, número, bairro...
Monovalorado Possui apenas um valor por instância dta_pedido
Multivalorado Pode ter mais de um valor por instância telefone (celular, residencial...)
Derivado Calculado a partir de outro(s) atributo(s) total = preço × quantidade
Chave Valor distinto para cada instância nro_pedido

Reunindo todos os tipos numa única entidade, o exemplo do material fica assim:

Pedido
nro_pedido dta_pedido nome_cliente quantidade vlr_unitário material telefone (1,n) total endereço_cliente ruanúmerobairrocidadeestadocep
chave primária derivado multivalorado composto (agrupa subatributos)

Valor nulo ou opcional: um atributo tem valor nulo quando a entidade não possui um valor para ele — por exemplo, nem todo cliente tem e-mail cadastrado. Identificamos um valor nulo pela sua cardinalidade no diagrama.

§Chave primária (Primary Key)

Um conjunto de atributos capaz de identificar univocamente uma instância de uma entidade é chamado de identificador — também conhecido como chave primária. No diagrama, ela aparece com o nome sublinhado ou com uma bolinha preenchida.

Funcionário
matrícula ← chave primária
nome cargo registro dta_nasc sexo

§Relacionamento

É uma associação entre entidades, representada por um losango ligado às entidades por linhas. O material traz vários exemplos do dia a dia:

Consulta

A notação (mínimo, máximo) ao lado de cada entidade indica a cardinalidade — quantas instâncias de uma entidade podem se relacionar com instâncias da outra:

Pedido
(1,n)
Recebe
(0,1)
Pagamento

Leitura da cardinalidade: cada aluno está matriculado em 1 e apenas 1 curso (1,1 do lado de Cursos), enquanto cada curso pode ter de 0 a N alunos lotados nele (0,N do lado de Alunos).

§Glossário rápido

Entidade
Objeto do mundo real sobre o qual se quer manter dados. Representada por retângulo.
Atributo
Propriedade que caracteriza uma entidade. Representado por oval.
Relacionamento
Associação entre entidades. Representado por losango.
Instância
Ocorrência específica de um tipo de entidade.
Chave primária
Atributo(s) que identifica(m) univocamente uma instância da entidade.
Cardinalidade
Indica quantas instâncias se relacionam, no formato (mínimo, máximo).
Atributo derivado
Calculado a partir de outros atributos já existentes.
Valor nulo
Ausência de valor de um atributo para uma instância específica.
